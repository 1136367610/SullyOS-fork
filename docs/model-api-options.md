# 模型参数兼容与 API 预设

设置的模型高级选项和预设编辑均提供「GPT‑5.1 参数兼容」。开启时，仅把 Chat Completions 请求中的 `max_tokens` 换成 `max_completion_tokens`，不改变额度数值，不因错误自动重发请求。

模型名同时含 GPT 和独立的 5.1 时自动识别，允许中间有中转商文字。保存配置或首次请求时，先持久化兼容选择，再显示一次提示。用户明确关闭后不再自动开启；更换 URL 或模型会重新判断。同名模型背后更换供应商模型时无法自动获知，可手动关闭并保存。

流式、温度和兼容开关均随 API 预设保存。其他入口选择预设时复制这些选项，之后独立保存；修改原预设不会自动修改已经复制的配置。保存当前 API 不会覆盖命名预设，需要编辑该预设。协同旧数据中已有的预设引用保留原来的联动行为，新选择使用快照。

独立 API 的显式流式设置优先于主 API。调用方已有的流式解析保持原样；非流式调用按选项升级并组装回 JSON。温度仅作用于原本携带温度的请求，保留思考模型原有的省略规则。

实现集中在 `utils/llmApiOptions.ts`。浏览器调用用 `prepareLlmRequest` 携带配置，OSContext 的统一出口用 `finalizeLlmRequest` 移除内部标记后发送。兼容选择按 URL + 完整模型名保存到 `os_llm_token_compat`，不包含 Key，随整机备份和本地镜像保存。

新建云端任务与即时请求通过 `cloudTokenOptions` 将上限放入 `llmExtraBody.max_completion_tokens`，同时省略旧 `maxTokens`，避免上游构建器重新加入旧参数。已排队任务保留创建时的配置，需要重新创建才使用新设置。情绪评估的凭据引用另带非敏感选项，需要配套更新主动消息 Worker。

回归覆盖：`utils/llmApiOptions.test.ts`、预设切换、配置归一化、视觉配置、协同预设及主动消息相关测试。测试不调用付费模型。
